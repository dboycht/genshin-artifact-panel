# 原神圣遗物评分 & 练度面板（本地版）

一个跑在你自己电脑上的原神圣遗物评分与角色练度面板工具。**数据不出本机**，不上传任何账号信息。

- 输入 **UID**，拉取角色展柜 → 直接展示**游戏内真实面板** + 逐件圣遗物评分 + 练度评分
- 也支持导入 **GOOD v3** / **莫娜占卜铺 mona.json** / 本工具备份，或**手动录入**
- 评分口径全部写在界面上、**可手动调整**，不搞黑箱

---

## 快速开始

1. 装 [Node.js](https://nodejs.org/) 18 或更新版本
2. 双击 **`启动.bat`**
3. 浏览器会自动打开 `http://127.0.0.1:8788/`

> `启动.bat` 只做一件事：用 Node 起一个**只监听本机回环地址**的小服务，然后打开浏览器。
> 关掉那个黑窗口就等于关闭工具。

### 为什么要有个本地服务？不能直接双击 index.html 吗？

因为 **Enka 的接口不返回 CORS 头**（实测：GET 响应无 `Access-Control-Allow-Origin`，OPTIONS 返回 405），
浏览器从 `file://` 页面直连会被同源策略拦下。所以需要一个本地服务把请求转发出去。

直接双击 `index.html` 时，"导入 JSON / 手动录入"这些离线功能仍然可用，**只有查 UID 不行**。

## 三种数据来源

| 来源 | 能拿到什么 | 限制 |
| --- | --- | --- |
| **UID 查询**（Enka.Network） | 展柜角色的**真实面板**、等级、命座、天赋、武器、5 件圣遗物的完整词条 | 只能拿到**角色展柜里的角色（游戏上限 8 个）**，且拿不到未装备的圣遗物 |
| **GOOD v3 / 莫娜 JSON 导入** | 你从其他工具导出的数据，可含多角色、整背包 | 面板由本工具**离线估算**（见下方「面板口径」） |
| **手动录入** | 自己填 | 同样走离线估算 |

### 查 UID 前请在游戏里做两件事

1. 把想查的角色放进「**角色展柜**」（最多 8 个）
2. 打开「**显示角色详情**」

否则接口不会返回任何角色数据 —— 这不是 bug。

> Enka 官方明确**禁止枚举 UID、批量刷库**。本工具只在你点「查询」时请求一次你填的那个 UID，
> 并按接口返回的 `ttl` 做本地缓存，不会做任何批量抓取。请也遵守这条。

## 评分口径（重要，请先读）

### 单件圣遗物评分

```
单件分 = Σ ( 副词条数值 ÷ 该词条「满档单发值」 ) × 该角色的词条权值
```

即社区说的「**滚数当量**」：一条满档副词条 = 1.0 个标准词条。

- 满档单发值按 5★ 圣遗物的 4 档体系：每档为满档值的 **70% / 80% / 90% / 100%**，四档**等概率**
- 暴击率与暴击伤害**取等权**（因为 1 条满档暴击率 3.89% 的价值 ≈ 1 条满档暴击伤害 7.77% 的一半），
  这恰好复现了社区惯用的双爆分 `CV = 2×暴击率 + 暴击伤害`
- **只有「有效词条」计入**，无效词条记 0 分（界面上会标灰）

> ⚠️ 有一处流传很广的数值错误：不少资料把「攻击力%／生命值%」的第 3 档写成 **5.3%**。
> 精确值是 **5.247%**，游戏内显示 **5.2%**。本工具用精确值计算、用显示值渲染。

### 角色练度评分（0~100）

**这个口径是本项目自定的。** 提瓦特小助手、ysin 等工具的练度权重**从未公开**，
不存在可以对齐的权威数值，所以这里不声称与任何第三方一致，并且界面上可以逐项手动改。

| 维度 | 权重 | 判据 |
| --- | --- | --- |
| 圣遗物 | 0.40 | 有效词条合计 ÷ 28 |
| 天赋 | 0.20 | 三项天赋平均等级 ÷ 10 |
| 角色等级 | 0.15 | (等级 − 1) ÷ 89 |
| 武器 | 0.15 | 0.6 × (等级 ÷ 90) + 0.4 × (精炼 ÷ 5) |
| 面板双爆 | 0.10 | 0.5 × min(暴击率,100) ÷ 70 + 0.5 × 暴击伤害 ÷ 140 |

另外有**充能门槛**：面板充能低于你填的需求时总分 ×0.85 并给出提示；超出需求不加分。

### 角色的「有效词条 + 权值」怎么来的？

依据角色**自身的突破加成属性**推断养成倾向（突破加什么通常就吃什么，这是从游戏数据本身得出的信号）：

| 突破加成 | 归入 | 主权重 |
| --- | --- | --- |
| 暴击率 / 暴击伤害 / 攻击力% | 暴击输出型 | 暴击率 1.0、暴击伤害 1.0、攻击力% 0.75 |
| 生命值% | 生命型 | 生命值% 1.0、双爆各 0.75 |
| 防御力% | 防御型 | 防御力% 1.0、双爆各 0.75 |
| 元素精通 | 精通型 | 元素精通 1.0、充能 0.75 |
| 元素充能效率 | 充能型 | 充能 1.0、双爆各 0.75 |
| （治疗/护盾定位角色名单） | 治疗型 | 生命值% 1.0、充能 1.0 |

界面里可以随时拖动滑杆改，改完自动重算。

### 面板口径：Enka 真值 vs 离线估算

- **查 UID** → 面板直接取 Enka 返回的 `fightPropMap`，那是**游戏算好的最终面板**，与游戏内一致
- **导入 / 手动录入** → 按静态数值表估算：角色基础 + 武器 + 圣遗物主副词条 + **能静态解析的 2 件套**。
  界面上会明确列出未计入项（4 件套条件效果、武器特效等）。

已知偏差：游戏内圣遗物**主词条的逐级数值是数据表而非公式**，本工具按 0 级↔+20 线性插值。
实测**生命值逐级零偏差**，攻击力等个别等级有 **±1** 的尾数差。所以离线面板整体标注为「估算」。
需要精确值请查 UID。

> 这不是偷懒：`genshin-db`、`m19e/artifact-scorer`、`genshin_artifact_auxiliary` 等 MIT/Apache 来源
> 都只有 0 级与 +20 两端的值，没有逐级表；而带逐级表的仓库没有 License（见下方「来源与致谢」）。

## 支持的导入导出格式

| 格式 | 方向 | 说明 |
| --- | --- | --- |
| 本工具备份 | 导入 / 导出 | 完整保留角色配置与权值，用于换机器或防止浏览器数据丢失 |
| **GOOD v3** | 导入 / 导出 | 社区事实标准。⚠️ 百分比键尾带下划线：`critRate_` / `critDMG_` / `atk_` / `enerRech_`；精通是 `eleMas`、元素伤是 `xxx_dmg_`。网上常见的 `em` / `er` / `anemo_` 写法是**错的** |
| **莫娜占卜铺 mona.json** | 导入 | 按 5 个部位数组组织，`item.equip` 为装备者名 |

导入时若某个套装/角色名匹配不上静态表，会在提示里逐条列出，不会静默丢弃。

## 数据与本机安全

- 服务**只绑定 `127.0.0.1`**，不对局域网/外网监听
- 代理**只允许访问 `enka.network`**，且 UID 必须是纯数字；不做任何批量或枚举
- **服务端不落任何玩家数据**；所有角色数据都存在**你的浏览器 localStorage** 里
- 「清空」按钮会抹掉本机保存的数据（建议先导出备份）
- 不使用 Cookie、不碰账号凭证、不读写游戏进程内存

## 开发

```bash
node tools/verify-gamedata.mjs     # 静态数值表自检（含绫华 90 级属性与官方值比对）
node tools/smoke-test.mjs          # 无头冒烟测试（65 项，合成数据，解析→评分→导入导出全链路）
node --max-old-space-size=6144 tools/build-gamedata.mjs <genshin-db 包目录>   # 重新生成静态表
```

## 已知限制

1. 只能拿到**角色展柜里的 8 个角色**（游戏硬上限，任何基于 Enka 的工具都绕不过）
2. 拿不到**未装备**的圣遗物，本工具也不做全背包管理
3. 离线面板有上述主词条 ±1 的插值偏差，且不计 4 件套条件效果与武器特效
4. 练度评分是本项目自定口径，**不是**任何第三方评分
5. 依赖 Enka.Network 这一第三方服务；游戏版本更新后 Enka 可能短暂返回 424（数据未适配），
   界面对各错误码都给了人话提示
6. 角色/武器/套装静态表来自 `genshin-db` v5.2.14（对应游戏 7.1），
   新版本角色可能尚未收录，遇到时界面会提示"静态表未收录"
